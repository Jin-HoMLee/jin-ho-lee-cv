## 1. Scope

Phase 6 makes the live site at `https://jinholee.is-a.dev/` discoverable and measurable. Two passive subsystems, both living in `web/`:

1. **SEO discoverability.** Sitemap (`sitemap-index.xml` + `sitemap-0.xml`) auto-generated by `@astrojs/sitemap`; a `robots.txt` allowing crawl and pointing at the sitemap; verification meta tags for Google Search Console and Bing Webmaster Tools.
2. **Privacy-friendly analytics.** A GoatCounter snippet emitted from `BaseLayout.astro`, gated by an env flag so it ships only in production builds and never in dev/PR builds. No cookies, no PII, no GDPR banner needed.

Both subsystems are additive — no changes to content layer, no changes to existing pages beyond adding head-section metadata.

## 2. Goal

After Phase 6:

- `https://jinholee.is-a.dev/sitemap-index.xml` resolves (200), lists every EN + DE page (root, project pages × 10 ids).
- `https://jinholee.is-a.dev/robots.txt` resolves (200), allows all user agents, references the sitemap.
- The site is verified in Google Search Console + Bing Webmaster Tools; sitemap is submitted in both.
- GoatCounter dashboard at `https://jinholee.goatcounter.com/` registers production page-views; dev builds (`just web-dev`) and PR/preview builds do not ping.
- Switching analytics provider later is a one-secret swap, not a code change.

## 3. Non-goals

- **Cookie/consent banner.** GoatCounter is cookie-free; with no PII collection there's no GDPR consent obligation. If we ever swap to a cookie-based provider, that's a separate decision.
- **Self-hosting analytics.** GoatCounter's hosted free tier is right-sized for a personal CV; self-hosting Umami / Plausible adds ongoing infra cost for no benefit at this scale.
- **DNS-based Search Console verification.** Meta-tag verification is faster and doesn't require coordinating with the is-a.dev registry. Can revisit if we ever lose the domain.
- **Per-page meta descriptions beyond the existing tagline.** `BaseLayout.astro` already emits `<meta name="description">` from `data.profile.tagline` (or `ogDescription` prop); Phase 6 doesn't author new copy.
- **WebSite / BreadcrumbList JSON-LD types.** Current `person.jsonld` covers Person + Project; adding WebSite/BreadcrumbList is low-value polish for a single-author personal CV.
- **PR previews of the indexed site.** `pages.yml` triggers only on push-to-main; PR CI cannot pre-verify post-deploy URLs. Smoke-checks run post-merge per the Phase 3 pattern.
- **Bing-specific structured data extensions** (IndexNow protocol, etc.). Submitting the sitemap is enough at this stage.
- **Analytics dashboards / weekly digest emails.** Out of scope — GoatCounter's built-in dashboard is sufficient.

## 4. Architecture

```text
web/astro.config.mjs          (MODIFIED: register @astrojs/sitemap integration)
    │
    ├─→ build emits:
    │     • web/dist/sitemap-index.xml   (NEW)
    │     • web/dist/sitemap-0.xml       (NEW)
    │
web/public/robots.txt          (NEW: static file)
    └─→ copied verbatim to web/dist/robots.txt

web/src/layouts/BaseLayout.astro  (MODIFIED: 3 new <head> lines, env-gated)
    │
    ├─→ if PUBLIC_GSC_VERIFY set:   emit <meta name="google-site-verification">
    ├─→ if PUBLIC_BING_VERIFY set:  emit <meta name="msvalidate.01">
    └─→ if PUBLIC_ANALYTICS_ENABLED === "true":  emit GoatCounter <script>

.github/workflows/pages.yml    (MODIFIED: pass env vars from secrets to `pnpm build`)
```

No changes to the Python content layer, the PDF renderer, or the JSON renderers. Phase 6 is entirely a `web/` + `.github/` change.

## 5. Module-level design

### 5.1 Sitemap

**Integration:** `@astrojs/sitemap` ([docs](https://docs.astro.build/en/guides/integrations-guide/sitemap/)). Pin to current major version; add to `package.json` dependencies.

**Config** in `web/astro.config.mjs`:

```js
import sitemap from "@astrojs/sitemap";

export default defineConfig({
  site: "https://jinholee.is-a.dev",
  // ... existing config
  integrations: [
    sitemap({
      i18n: {
        defaultLocale: "en",
        locales: { en: "en-US", de: "de-DE" },
      },
      filter: (page) => !page.includes("/og/") && !page.includes("/404"),
    }),
  ],
});
```

**Output:** `web/dist/sitemap-index.xml` + `web/dist/sitemap-0.xml` listing all EN/DE static pages and dynamically generated project pages. Astro's sitemap integration enumerates routes via `getStaticPaths`, so the 9 project pages × 2 langs are automatically included.

**Excluded:** OG image routes (`/og/*.png`), 404, anything Astro would otherwise emit that shouldn't be indexed.

### 5.2 robots.txt

`web/public/robots.txt` (static, committed):

```text
User-agent: *
Allow: /

Sitemap: https://jinholee.is-a.dev/sitemap-index.xml
```

Astro copies `web/public/` verbatim to `web/dist/`; no integration required.

### 5.3 Verification meta tags

In `BaseLayout.astro`, immediately after the existing `<meta name="description">` line:

```astro
---
// ... existing frontmatter
const gscVerify = import.meta.env.PUBLIC_GSC_VERIFY;
const bingVerify = import.meta.env.PUBLIC_BING_VERIFY;
---
{gscVerify && <meta name="google-site-verification" content={gscVerify} />}
{bingVerify && <meta name="msvalidate.01" content={bingVerify} />}
```

When env vars are unset, the tags are not emitted. This keeps dev builds, forks, and PR builds from impersonating ownership of the production property.

### 5.4 Analytics snippet

GoatCounter snippet, emitted just before `</head>` in `BaseLayout.astro`:

```astro
---
const analyticsEnabled = import.meta.env.PUBLIC_ANALYTICS_ENABLED === "true";
const analyticsEndpoint = import.meta.env.PUBLIC_ANALYTICS_ENDPOINT;
---
{analyticsEnabled && analyticsEndpoint && (
  <script
    data-goatcounter={analyticsEndpoint}
    async
    src="//gc.zgo.at/count.js"
  ></script>
)}
```

**Default behavior:** with `PUBLIC_ANALYTICS_ENABLED` unset (dev, PR previews, forks), no `<script>` is emitted. Production builds set the flag via `pages.yml`.

**Provider portability:** swapping to Plausible/Counter.dev is a `pages.yml` env change + a small `BaseLayout.astro` script-template tweak. Endpoint URL is env-driven so swap is two env values, not a code edit, for any provider whose snippet shape matches GoatCounter's.

### 5.5 GitHub Actions wiring

In `.github/workflows/pages.yml`, the `Build site` step gains an `env:` block:

```yaml
      - name: Build site
        env:
          PUBLIC_GSC_VERIFY: ${{ secrets.GSC_VERIFY }}
          PUBLIC_BING_VERIFY: ${{ secrets.BING_VERIFY }}
          PUBLIC_ANALYTICS_ENABLED: "true"
          PUBLIC_ANALYTICS_ENDPOINT: "https://jinholee.goatcounter.com/count"
        run: pnpm --dir web build
```

`PUBLIC_ANALYTICS_ENABLED` and `PUBLIC_ANALYTICS_ENDPOINT` are hardcoded (the GoatCounter endpoint is public, no need to hide it). `GSC_VERIFY` and `BING_VERIFY` are pulled from repo secrets — verification codes are not strictly secret (they appear in page HTML) but storing them in secrets keeps verification tied to repo settings rather than committed code, which makes rotation cleaner.

Astro reads `PUBLIC_*` env vars at build time and inlines them into the bundle ([Astro env docs](https://docs.astro.build/en/guides/environment-variables/)).

## 6. User-side actions (not code)

These are one-time setup steps the user performs **after** the Phase 6 code merges:

1. **Sign up for GoatCounter.** Pick subdomain (proposed: `jinholee.goatcounter.com`). Free tier. Confirm subdomain matches `PUBLIC_ANALYTICS_ENDPOINT` in `pages.yml`.
2. **Create Google Search Console property** at `search.google.com/search-console` for `https://jinholee.is-a.dev/`. Choose "URL prefix" property → meta-tag verification method → copy the `content` value → add as repo secret `GSC_VERIFY` (Settings → Secrets and variables → Actions).
3. **Same for Bing Webmaster Tools** at `bing.com/webmasters`. Copy verification code → repo secret `BING_VERIFY`.
4. **Trigger a deploy** (push to main, or `gh workflow run Pages`). Verify meta tags appear in `curl https://jinholee.is-a.dev/ | grep -E '(google-site-verification|msvalidate)'`.
5. **Confirm verification in Search Console + Bing.** Once green, submit `https://jinholee.is-a.dev/sitemap-index.xml` in each.
6. **Test a page-view in GoatCounter.** Visit the site in an incognito window; confirm a hit appears in the GoatCounter dashboard within ~1 min.

Phase 6 code ships in a state where deploying with all four secrets unset is a graceful no-op (no verification tags, no analytics snippet, just the sitemap + robots.txt). The user can complete steps 1-3 in any order, and the next deploy picks them up.

## 7. Testing

### 7.1 Local (no env set)

- `just web-build` → assert `web/dist/sitemap-index.xml` exists, `web/dist/sitemap-0.xml` exists, `web/dist/robots.txt` exists.
- `grep -c "<url>" web/dist/sitemap-0.xml` → expect 22 entries (2 homepages + 10 project pages × 2 langs).
- `grep -E "(google-site-verification|msvalidate|goatcounter)" web/dist/index.html` → expect zero matches (env unset).
- `cat web/dist/robots.txt` → assert content matches expected template.

### 7.2 Local (env set)

- `PUBLIC_GSC_VERIFY=test PUBLIC_BING_VERIFY=test PUBLIC_ANALYTICS_ENABLED=true PUBLIC_ANALYTICS_ENDPOINT=https://example.goatcounter.com/count pnpm --dir web build`
- `grep 'google-site-verification' web/dist/index.html` → 1 match.
- `grep 'msvalidate.01' web/dist/index.html` → 1 match.
- `grep 'goatcounter' web/dist/index.html` → 1 match.

### 7.3 CI smoke-checks (extend `pages.yml` `Smoke-check build outputs` step)

- Assert `web/dist/sitemap-index.xml` and `web/dist/robots.txt` exist.
- Grep `web/dist/index.html` for the three production meta/script tags (verification × 2 + analytics).

### 7.4 Post-deploy (manual, one-time per setup step)

- `curl -fsSI https://jinholee.is-a.dev/sitemap-index.xml` → 200.
- `curl -fsSI https://jinholee.is-a.dev/robots.txt` → 200.
- `curl -fs https://jinholee.is-a.dev/ | grep -E '(google-site-verification|msvalidate|goatcounter)'` → all three present.
- Search Console + Bing show "Verified" status.
- GoatCounter dashboard registers a test visit.

## 8. Known caveats

- **`pages.yml` triggers only on push-to-main**, not on PR. PR CI cannot pre-verify post-deploy URLs. Per Phase 5 precedent, the PR test plan marks post-deploy items as "verifies on merge" and the user/agent watches `gh run watch` after merge for confirmation.
- **Search Console verification can be slow** to propagate after first deploy (Google may take a few minutes to fetch the homepage and find the meta tag). Plan to retry after ~5 min if first attempt fails.
- **CNAME PUT API behavior carries over from Phase 5.** No new domain config needed in Phase 6, but if the domain ever changes, the existing `gh api -X PUT repos/.../pages -f cname=...` flow still applies — Phase 6 doesn't change it.
- **GoatCounter subdomain is permanent.** Pick `jinholee` (matches the domain). Cannot easily rename later without re-verifying analytics in search consoles and migrating historical counts.
- **Astro's `i18n.routing.prefixDefaultLocale: false` means EN routes have no `/en/` prefix.** Sitemap integration's `i18n` config block needs to match — if misconfigured, EN pages will be emitted with the wrong language attribute or duplicated. Test §7.1 includes the URL count check (22) which would catch double-emission.
- **CSP not configured currently, but GoatCounter requires specific directives if one is added later.** Both the script load and the beacon target the same origin: `script-src https://gc.zgo.at; connect-src https://gc.zgo.at`. Document this here so a future CSP addition doesn't silently break analytics. Flagged by the @claude PR #27 review on 2026-05-28.

## 9. Open questions

None. All decisions resolved in brainstorming:

- Provider: GoatCounter (free, hosted, GDPR-clean).
- Verification: meta-tag (not DNS).
- Subdomain: `jinholee.goatcounter.com`.
- Bundle scope: SEO + analytics together (not split).
- Secrets storage: GitHub Actions repo secrets (not in-code or in DNS).
