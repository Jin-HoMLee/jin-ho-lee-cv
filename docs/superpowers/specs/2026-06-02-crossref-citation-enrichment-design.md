# Build-time Crossref citation-count enrichment — design

**Issue:** [#57](https://github.com/Jin-HoMLee/jin-ho-lee-cv/issues/57) (split from #47)
**Date:** 2026-06-02
**Status:** Approved — ready for implementation plan

## Goal

Enrich publications with **citation counts** (`is-referenced-by-count`) fetched
from **Crossref** (key-free; *not* OpenAlex, which began requiring an API key
2026-02-13), and present them as *indicative* impact signals on the website and
in the JSON-LD machine format.

The counts are fetched **at build time only** and baked into committed artifacts —
no third-party runtime JavaScript, preserving the site's privacy-friendly stance.

## Non-goals / out of scope

- Plain-text CV, PDF, and JSON Resume are **untouched**. The committed cache makes
  adding any of them a trivial follow-up.
- No live/runtime fetching. No per-build network calls.
- No attempt to match Google Scholar numbers — Crossref undercounts and lags, and
  we frame the figures honestly as *indicative*.

## Core principle alignment

The cache is a **lockfile, not content**: a pinned, committed snapshot *derived
from* `content/publications.bib` via Crossref, regenerated by an explicit command
and reviewed on diff — the same semantics as `poetry.lock` or this repo's golden
snapshots. It therefore lives **outside `content/`**, which CLAUDE.md reserves for
hand-authored source of truth. It is not build output (`dist/`, gitignored) and not
a test fixture — it is a committed build *input*, so it gets a dedicated `data/` home.

## Architecture

### Data flow

```
content/publications.bib  ──load_publications()──►  [Publication × N]
                                                          │
data/citations.json       ──load_citation_cache()──►  {doi: count}
                                                          │
                                   enrich_publications(pubs, cache)
                                                          │
                                        [Publication + citation_count]
                                          │                     │
                                  render_web_data        render_jsonld
                                  (bar chart + list)     (interactionStatistic)
```

The networked fetcher (`scripts/fetch_citations.py`) is **off** this path — it only
runs manually via `just refresh-citations` and writes `data/citations.json`. Every
normal build (`just build`, `just web-data`, CI) reads the committed cache and never
touches the network, so output stays deterministic and offline-safe.

### Components

#### `scripts/bib_loader.py` — one new field, stays pure

Add to the frozen `Publication` dataclass:

```python
citation_count: int | None = None
```

Defaulting to `None` keeps it backward-compatible — every existing constructor and
test that omits it is unaffected. `bib_loader` remains **network- and cache-free**;
it knows nothing about citations beyond carrying the optional field.

#### `scripts/citations.py` — new module, the only cache consumer

```python
def load_citation_cache(path: Path) -> dict[str, int]:
    """Read the committed cache → {doi: count}. Missing/unreadable file → {} (offline-safe)."""

def enrich_publications(
    pubs: list[Publication], cache: dict[str, int]
) -> list[Publication]:
    """Return new records (via dataclasses.replace) with citation_count set where the
    DOI is in the cache; absent DOI or no DOI → citation_count stays None."""
```

- **Missing cache file → `{}`** → every publication renders with no count, no error.
  This is the offline-degrade contract.
- Pure, deterministic, no I/O beyond reading the one JSON file.

Renderers that want counts compose:
`enrich_publications(load_publications(bib), load_citation_cache(cache))`.

#### `scripts/fetch_citations.py` — new module, the *only* networked code

Run manually via `just refresh-citations`. Steps:

1. Load DOIs from `content/publications.bib` (via `load_publications`).
2. For each DOI, GET `https://api.crossref.org/works/{doi}` using stdlib
   **`urllib.request`** (no new dependency), with a polite `User-Agent` header
   carrying the CV's public contact email — read from `content/personal.yaml`
   (`personal.email`), the single source of truth (always present; no fallback needed).
3. Extract `message.is-referenced-by-count` (a non-negative int).
4. **Robust merge:** start from the existing cache; on a per-DOI fetch/parse error,
   **retain the existing cached value** rather than dropping it (one transient 5xx
   can't wipe a number). Log which DOIs were refreshed vs. retained vs. failed.
5. Write `data/citations.json` with **keys sorted** for stable diffs.

Determinism caveat: `fetched_at` uses today's date — this is the one
non-deterministic field, and it lives only in the manually-run fetcher, never in a
build. Tests mock both the network (`urlopen`) and the date.

#### `data/citations.json` — committed cache (new top-level `data/`)

```json
{
  "_generated_by": "just refresh-citations — do not hand-edit",
  "source": "crossref",
  "fetched_at": "2026-06-02",
  "counts": {
    "10.3390/cancers11121877": 58,
    "10.5772/intechopen.95597": 12
  }
}
```

- **Committed** (not gitignored) — this is what makes `just build` and CI offline and
  deterministic.
- `_generated_by` self-documents that it is generated, since JSON can't carry comments.
- `counts` keyed by bare normalized DOI (matching `Publication.doi`), values are
  `is-referenced-by-count`.

### Web — new SVG bar chart + per-paper counts

#### `web/src/components/PublicationsCitations.astro` (new)

- Horizontal **SVG** bars, **citations-per-paper, sorted descending**, rendering only
  publications that *have* a count (DOI present and in cache). Papers without a count
  are simply omitted from the bars (they remain in the pie, cumulative chart, and list).
- Axis labels are short (e.g. `venue 'YY`); the **full title + exact count** surface in
  the hover/tap/keyboard **tooltip**, reusing the existing tooltip pattern from
  `PublicationsChart.astro` / `PublicationsCumulative.astro` (mouse, touch, and
  keyboard-focus parity; dismiss on outside tap).
- Honest caption: **"Crossref citations · indicative (undercounts vs. Google Scholar)."**
- **Shown for all targets**, like the pie and cumulative charts — it's an indicative
  visual summary, not the verbatim publication list (which stays target-gated).
- Empty state: if no publication has a count (e.g. cache missing), the component
  renders nothing (no empty axes).

#### Placement

Full-width row **below** the existing pie + cumulative row in `PublicationsList.astro`
(horizontal bars need the width). Layout stays responsive.

#### `web/src/components/PublicationsList.astro`

In the full verbatim list (revealed for the comp-bio target), append **`· cited by N`**
to each paper's existing DOI/meta line — only when `citation_count` is present.

#### `web/src/types/content.ts`

Add `citation_count: number | null` to the `Publication` interface. The value rides into
`content.{en,de}.json` automatically via `dataclasses.asdict` in `render_web_data` once
enrichment runs — `render_web_data` just needs to enrich before dumping.

### JSON-LD — `interactionStatistic`

`render_jsonld._publications` adds, per `ScholarlyArticle`, when
`citation_count is not None`:

```json
"interactionStatistic": {
  "@type": "InteractionCounter",
  "interactionType": "https://schema.org/CiteAction",
  "userInteractionCount": 58
}
```

`render_jsonld.main` enriches pubs (`enrich_publications(load_publications(...),
load_citation_cache(...))`) before composing the graph. This reinforces the
machine-readable-CV story for crawlers and LLM ingestion.

## Renderers touched

| Renderer | Change |
|---|---|
| `render_web_data` | enrich pubs; `citation_count` flows into `content.{en,de}.json` |
| Web components | new `PublicationsCitations.astro`; `PublicationsList` per-paper count; `content.ts` type |
| `render_jsonld` | enrich pubs; `interactionStatistic` per work |
| PDF / plain text / JSON Resume | **untouched** |

## Build / commands

- **New:** `just refresh-citations` → `python -m scripts.fetch_citations` (the only
  recipe that hits the network).
- `just web-data`, `just web-build`, `just build-jsonld`, `just build-formats`,
  `just web-llms` etc. read the committed cache only — no network, no behavior change
  beyond the enriched fields.
- CI is unchanged structurally and never fetches; it builds against the committed cache.

## Testing

- **`tests/test_citations.py`**
  - `load_citation_cache`: present file, **missing file → `{}`**, empty/garbage file → `{}`.
  - `enrich_publications`: DOI match sets count; DOI absent from cache → `None`;
    publication with no DOI → `None`; original records unmutated (returns new objects).
- **`fetch_citations` tests** (network mocked — `urlopen` patched)
  - parse `is-referenced-by-count` from a representative Crossref JSON payload;
  - **merge-retain-on-error**: a failing DOI keeps its prior cached value;
  - deterministic, **sorted-key** output.
- **Staleness guard test:** every DOI key in `data/citations.json` resolves to a real
  publication DOI (no orphan/stale keys). A publication DOI *missing* from the cache is
  **advisory only** — it must **not** fail (offline-degrade is the contract).
- **Snapshots:** regenerate `content.{en,de}.json` and `person.jsonld` via
  `just snapshots-update`; eyeball the diff (new `citation_count` / `interactionStatistic`).
- **Web bar chart:** visual verification via the repo's local Playwright flow
  (screenshot the publications section; confirm bars, tooltip, and caption render and
  that the section degrades gracefully when counts are absent).

All of `just validate`, `just test`, `just lint` stay green before merge.

## Honesty framing (carried from #47 triage)

Crossref counts lag and undercount versus Google Scholar. Every surface that shows a
number labels it **indicative** (web caption; the figures are never presented as
authoritative totals). No comparative/ranking language beyond the neutral bar chart.
