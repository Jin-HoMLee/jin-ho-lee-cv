# Design: Phase 5 — Polish (custom domain + project pages + OG images + chart tooltips)

**Date:** 2026-05-26
**Owner:** Jin-Ho Lee
**Parent spec:** [`2026-05-21-codified-cv-design.md`](./2026-05-21-codified-cv-design.md)
**Predecessor phase:** Phase 4 — Machine formats + publications chart (merged 2026-05-25, commit `5f3ce71`)

## 1. Scope

Phase 5 ships four additive polish items, bundled in a single phase:

1. **Custom domain (parameterized).** A central `SITE_DOMAIN` constant; Astro `site`/`base` flip to the custom domain; `web/public/CNAME` created. Domain name itself is a placeholder until the implementation step.
2. **Project deep-dive pages.** One static page per project at `/projects/{id}/` (EN) and `/de/projects/{id}/` (DE), generated by a dynamic Astro route. Renders the same fields the homepage already inlines — no new content authored.
3. **OG images (Satori, build-time).** Per-page 1200×630 PNGs generated by `astro-og-canvas` from existing content JSON, rendered in the "magazine" style chosen during brainstorming (soft tinted background, large accent-colored title, metadata footer row).
4. **Chart hover tooltips.** Pie + cumulative chart components gain a tiny inline `<script>` that shows a tooltip on `mouseenter` and a tap-toggle on touch devices.

All four are independent in code but share the spec/plan/branch overhead. Bundled for the same reason Phase 4 was — none ships meaningful mid-phase value on its own.

## 2. Goal

After Phase 5:

- `https://{SITE_DOMAIN}/` and `https://{SITE_DOMAIN}/de/` serve the website (with `https://jin-homlee.github.io/jin-ho-lee-cv/` continuing to redirect/work as a fallback).
- `https://{SITE_DOMAIN}/projects/L1/` (and the other 8 ids, in both langs) serve standalone project pages.
- Every page declares `<meta property="og:image">` pointing to a generated 1200×630 PNG. Sharing a CV link on LinkedIn/Slack/Twitter shows a branded preview card.
- Hovering a pie slice or a year on the cumulative chart pops up a tooltip with label + count + percentage / year + cumulative + delta.
- The codified-CV project is feature-complete; subsequent work is content-only.

## 3. Non-goals

- **Per-project narrative prose.** Project pages render the existing YAML fields verbatim — no new long-form text. (Brainstorming explicitly chose "same fields, stable URL only" over "expanded writeup.")
- **Homepage redesign.** The inline expansion of projects in the experience section stays untouched, with one small addition: a permalink anchor per project block.
- **Click-to-filter chart interactions.** Tooltips only. No click-to-filter, no list↔chart hover coupling. Brainstorming chose hover tooltips only.
- **Animated chart reveals.** Out of scope; polish without behavior change is not worth the complexity.
- **PR previews of the deployed site or OG images.** Same rationale as Phase 3 §3 — adds CI complexity for marginal value.
- **404 page customization.** Astro's default is fine.
- **Sitemap.xml / robots.txt enhancements** beyond what Astro already emits.
- **Custom domain email** (MX records etc.). DNS instructions cover the CNAME only.
- **A11y audit of OG images.** OG images are off-page assets; `<meta property="og:image:alt">` is set, but no further work.
- **Visual regression on project pages / OG images.** Out of scope per parent spec §8.

## 4. Architecture

```
content/*.yaml + *.bib
    │
    └─→ scripts/content_loader.py            (UNCHANGED)
            │
            ├─→ scripts/render_web_data.py   (UNCHANGED)
            │       └─→ web/src/data/content.{en,de}.json
            │               │
            │               └─→ Astro pages:
            │                     • index.astro                    (UNCHANGED)
            │                     • de/index.astro                 (UNCHANGED)
            │                     • projects/[id].astro            (NEW — dynamic route)
            │                     • de/projects/[id].astro         (NEW — dynamic route)
            │                                │
            │                                ↓
            │                       astro-og-canvas integration   (NEW)
            │                                │
            │                                └─→ web/dist/og/*.png (per-page OG images)
            │
            ├─→ scripts/render_jsonld.py     (MODIFIED: read SITE_DOMAIN)
            ├─→ scripts/render_jsonresume.py (MODIFIED: read SITE_DOMAIN)
            └─→ scripts/render_text.py       (MODIFIED: read SITE_DOMAIN)

scripts/config.py (NEW) ─→ SITE_DOMAIN, PAGES_BASE_URL
```

No changes to the Python content layer (`content_loader.py`, `bib_loader.py`, `langstring.py`). Astro gains:
- A new constants module
- A new dynamic route (× 2 langs)
- A new page component (`ProjectPage.astro`)
- A new OG image template (`lib/og.tsx`)
- Inline tooltip scripts in the existing two chart components

Existing Python renderers are touched only to swap a hardcoded URL constant for a `SITE_DOMAIN`-derived one.

## 5. Module-level design

### 5.1 `scripts/config.py` (new)

Tiny module holding URL-related constants. One place to flip the domain.

```python
"""Site-wide configuration constants. Read by every renderer that emits a URL."""

SITE_DOMAIN = "cv.jinholee.com"   # placeholder; finalized at implementation time
PAGES_BASE_URL = f"https://{SITE_DOMAIN}"
```

**Tests** (`tests/test_config.py`):
- `test_site_domain_is_bare_host` — no scheme, no path, no trailing slash.
- `test_pages_base_url_format` — matches `^https://[a-z0-9.-]+$`.

### 5.2 `scripts/render_jsonld.py`, `render_jsonresume.py`, `render_text.py` (modify)

Each currently has a hardcoded `https://jin-homlee.github.io/jin-ho-lee-cv/` somewhere. Replace with `from scripts.config import PAGES_BASE_URL` and use `f"{PAGES_BASE_URL}/"` etc.

For `render_jsonld.py`, also add per-project `CreativeWork` entries in `@graph` pointing to `{PAGES_BASE_URL}/projects/{id}/` — so project pages get indexed as part of the Person's graph. Each entry uses fields from the project YAML:

```python
{
  "@type": "CreativeWork",
  "name": project["title"],
  "url": f"{PAGES_BASE_URL}/projects/{project['id']}/",
  "description": project["summary"],
  "dateCreated": project["period"]["start"],
  "keywords": project["technologies"],
}
```

`render_jsonresume.py` already emits `projects[]` per JSON Resume schema. The only change is `projects[i].url` becoming `f"{PAGES_BASE_URL}/projects/{id}/"`.

`render_text.py` references the site URL in the header. Same single-line swap.

**Tests** (additions to existing files):
- `tests/test_render_jsonld.py::test_graph_includes_project_creativeworks` — assert one `CreativeWork` per project, URL shape matches.
- `tests/test_render_jsonresume.py::test_project_urls_present` — assert every `projects[i].url` is non-empty and starts with `PAGES_BASE_URL`.
- `tests/test_render_text.py::test_header_url_uses_site_domain` — assert header line contains `SITE_DOMAIN`.

### 5.3 `web/src/lib/site-config.ts` (new)

JS-side mirror of the Python constant. One source of truth would require codegen; for now, two declarations of the same string is acceptable (small surface, low churn). A `tests/test_config_parity.py` test reads both files and asserts the strings match.

```ts
export const SITE_DOMAIN = "cv.jinholee.com";
export const PAGES_BASE_URL = `https://${SITE_DOMAIN}`;
```

### 5.4 `web/astro.config.mjs` (modify)

```js
import { defineConfig } from "astro/config";
import tailwind from "@astrojs/tailwind";
import { ogImagesIntegration } from "astro-og-canvas";

export default defineConfig({
  site: "https://cv.jinholee.com",   // was: "https://jin-homlee.github.io"
  base: "/",                          // was: "/jin-ho-lee-cv/"
  trailingSlash: "always",
  i18n: {
    defaultLocale: "en",
    locales: ["en", "de"],
    routing: { prefixDefaultLocale: false },
  },
  integrations: [tailwind(), ogImagesIntegration()],
});
```

The `base` change from `/jin-ho-lee-cv/` to `/` is mechanical but touches every relative URL emitted by Astro. The CI smoke test should grep `web/dist/index.html` for `/jin-ho-lee-cv/` and fail if found (catches stale paths).

### 5.5 `web/public/CNAME` (new)

Single line containing the bare domain:

```
cv.jinholee.com
```

GitHub Pages reads this on deploy and routes the custom domain. The first deploy after this lands triggers automatic Let's Encrypt cert provisioning (~minutes).

**Manual step** (documented in the impl plan): set CNAME `cv` → `jin-homlee.github.io.` at the DNS registrar before merging.

### 5.6 `web/src/pages/projects/[id].astro` (new) + `web/src/pages/de/projects/[id].astro` (new)

Both files are nearly identical, differing only in imported data and `lang` prop. EN version:

```astro
---
import contentEn from "../../data/content.en.json";
import BaseLayout from "../../layouts/BaseLayout.astro";
import ProjectPage from "../../components/ProjectPage.astro";

export function getStaticPaths() {
  const ids = Object.keys(contentEn.projects);
  return ids.map((id) => ({ params: { id } }));
}

const { id } = Astro.params;
const project = contentEn.projects[id as string];
const labels = contentEn.labels;
---
<BaseLayout lang="en" data={contentEn} title={project.title}>
  <ProjectPage project={project} labels={labels} lang="en" />
</BaseLayout>
```

DE counterpart imports `content.de.json` and passes `lang="de"`. Acceptable duplication; consolidation is a one-line refactor when more locales arrive.

### 5.7 `web/src/components/ProjectPage.astro` (new)

Renders the project's existing fields. Sections, in order:

1. Breadcrumb: `← Back to CV` link to homepage anchor for this project (`/#L1`).
2. Title (large, `#1f3a68`).
3. Role · period (sub-line).
4. Summary (short paragraph from `project.summary`).
5. Technologies (chip row).
6. Contributions (`<ul>` with `·` bullets).
7. Outcome (callout block — light tinted background).
8. Footer: language switcher to the DE/EN counterpart of this project.

No new fields needed in YAML; every field already exists.

**Tests:** No new Python tests. The `pnpm build` in CI exercises the whole route — a missing field or type error fails the build.

### 5.8 `web/src/components/ProjectsSection.astro` (modify)

Add a small `↗` permalink anchor next to each project's title in the inline expansion. Roughly 3 lines of JSX. Points to `/projects/{id}/` (EN) or `/de/projects/{id}/` (DE).

### 5.9 `web/src/lib/og.tsx` (new)

JSX template consumed by `astro-og-canvas`. Implements the **magazine** style chosen during brainstorming:

```tsx
import type { OGImageRoute } from "astro-og-canvas";

export const getOGTemplate = (data: {
  kicker: string;        // e.g. "Jin-Ho Lee — Project Brief" or "Jin-Ho Lee — CV"
  title: string;         // project title or profile tagline
  subtitle?: string;     // optional role/headline
  meta?: { label: string; value: string }[];  // 1-3 metadata pills at the bottom
}): OGImageRoute => ({
  /* template definition — soft background #f4f7fb, uppercase #1f3a68 kicker
     letterspaced, large #1f3a68 title (font-size 64), optional subtitle in
     #444, metadata row at bottom in two-line format (small label / bigger value) */
});
```

The integration auto-routes generated images to `/og/{slug}.png` based on `getStaticPaths`. Per-page wiring in `BaseLayout.astro`:

```astro
<meta property="og:image" content={`${PAGES_BASE_URL}/og/${ogSlug}.png`} />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta property="og:image:alt" content={ogAlt} />
<meta name="twitter:card" content="summary_large_image" />
```

Where `ogSlug` is derived from the page (e.g. `index-en`, `projects-L1-de`) and `ogAlt` is a short factual description.

### 5.10 `web/src/layouts/BaseLayout.astro` (modify)

Extend the props interface to accept an optional `ogSlug` and `ogAlt`. Inject the OG/Twitter meta tags shown above. Also add `<link rel="canonical" href={`${PAGES_BASE_URL}${Astro.url.pathname}`} />` and the missing `<meta property="og:title">` + `og:description` + `og:url` + `og:type`. `og:type` is `"profile"` on homepage, `"article"` on project pages.

### 5.11 `web/src/components/PublicationsChart.astro` + `PublicationsCumulative.astro` (modify)

Each gains:

1. An inline `<style>` block defining `.tooltip` (small dark pill, 13px white text, 6px padding, 4px border-radius, drop shadow, `pointer-events: none`, hidden by default).
2. An inline `<script>` block attaching `mouseenter` / `mouseleave` / `mousemove` to each pie path or cumulative-line vertex. The script computes label/percentage/delta from data attributes baked onto the SVG elements at render time, positions an absolutely-positioned `<div class="tooltip">` near the cursor, and toggles `[hidden]`.
3. Touch handling: a `touchstart` listener that toggles the tooltip on tap (since `mouseenter` is unreliable on touch).

No external dependency. Roughly 40 lines of JS per chart. Each script is self-contained inside its component file — no cross-component coupling.

**Tests:** None. Tooltip behavior is verified manually post-deploy. Static SVG (the fallback if JS doesn't run) is already covered by the existing build.

### 5.12 `package.json` (modify)

Add `astro-og-canvas` dependency (pinned major). Run `pnpm install` to update lockfile.

### 5.13 `web/.gitignore` (modify)

Add `dist/og/` for clarity (the parent `dist/` is already ignored). Belt-and-suspenders.

### 5.14 `.github/workflows/pages.yml` (modify)

The existing build step already runs `pnpm --dir web build`, which now also runs the OG image generation as part of Astro's build. Add one post-build smoke step:

```yaml
- name: Smoke-check build outputs
  run: |
    test -f web/dist/index.html
    test -f web/dist/de/index.html
    test -f web/dist/projects/L1/index.html
    test -f web/dist/de/projects/L1/index.html
    test -f web/dist/og/index-en.png
    test -f web/dist/og/projects-L1-en.png

```

The L1 id is a representative spot-check; if the dynamic route enumerates 0 projects, all 9 paths would fail simultaneously.

## 6. Failure modes

| Failure | Detection | Recovery |
|---|---|---|
| Custom domain DNS misconfigured | Site unreachable on `cv.jinholee.com`; github.io URL still works | Revert `astro.config.mjs`, delete `CNAME`, redeploy — github.io URL keeps the site live in the meantime |
| `astro-og-canvas` font missing | OG image renders as blank/tiny — caught by the >5KB check | Bundle the font with the integration; CI fails before deploy |
| `getStaticPaths` returns 0 projects (content JSON missing) | Astro build fails loudly during `pnpm build` | Pages workflow already runs `render_web_data` first; failure surfaces immediately |
| Project id in URL doesn't exist (`/projects/X9/` typo) | Astro emits 404 for unknown paths | Default 404 page acceptable |
| Tooltip JS errors on old browsers | Static SVG remains; only the tooltip is lost | Graceful degradation by design — no recovery needed |
| `og:image` URL is stale after a domain change | All emitted URLs derive from `SITE_DOMAIN`/`PAGES_BASE_URL` | Single-string edit propagates everywhere |
| Stale `/jin-ho-lee-cv/` paths in built HTML after base change | Smoke `grep` in `pages.yml` fails the build | Find and fix the offending hardcoded path |
| TS/Python `SITE_DOMAIN` drift | `tests/test_config_parity.py` reads both files, asserts equal | Update whichever lags |
| `astro-og-canvas` major bump breaks API | Lockfile pin + `pnpm build` in CI catches | Pin major in `package.json` |
| OG image generation slow → CI timeout | Astro caches; first build ~30s, incremental builds skip unchanged | Monitor; if it becomes a problem, exclude `dist/og/` from the regen on docs-only commits |

## 7. Testing

| Layer | Tool | What |
|---|---|---|
| Unit (Python) | pytest | `tests/test_config.py`: `SITE_DOMAIN` shape, `PAGES_BASE_URL` format. `test_config_parity.py`: TS + Python constants match. Additions to existing render tests assert URLs use `PAGES_BASE_URL`. |
| Build (Astro) | `pnpm build` in CI | All 18 project HTML files emit. OG images emit. No stale `/jin-ho-lee-cv/` paths in output. |
| Smoke (CI) | shell tests in `pages.yml` | File-exists checks + minimum size for one OG image. |
| Schema | existing pytest + jsonschema | JSON Resume / JSON-LD continue to validate after URL changes. |
| Manual (post-deploy) | Human review | Hover tooltip behavior on desktop. Tap behavior on iPhone Safari. LinkedIn / Twitter / Facebook share preview shows the right OG card. Project page renders identically to inline expansion. |

Explicitly skipped: pixel-level OG image regression, automated cross-browser, visual regression on project pages (parent spec §8).

## 8. Migration / rollback

Fully additive. Each item is independently reversible:

- **Custom domain:** revert `astro.config.mjs` + `scripts/config.py` + `web/src/lib/site-config.ts`. Delete `web/public/CNAME`. github.io URL keeps working immediately.
- **Project pages:** delete `pages/projects/[id].astro` (+ `de/` twin) and `ProjectPage.astro`. Remove the permalink `↗` from `ProjectsSection.astro` (3 lines).
- **OG images:** uninstall `astro-og-canvas`, delete `lib/og.tsx`, remove `og:image` meta in `BaseLayout.astro`.
- **Chart tooltips:** delete the `<script>` + `<style>` blocks in both chart components. Charts revert to pure static SVG.

No content/ changes; no Python content-layer changes; no breaking changes to existing renderers.

## 9. Sequencing for after Phase 5

Phase 5 closes the codified-CV project. After this, the repo enters maintenance mode: content updates land in `content/`, everything else regenerates. Natural follow-ups (not in any planned phase):

- **More languages.** Schema already accommodates them; would mean a new `content/*.{xx}.yaml` set + adding the locale to `astro.config.mjs`.
- **PR-preview deploys.** Worth adding only if collaboration ramps up. Wires Pages workflow to a per-PR subdomain.
- **Content-collection refactor.** Replace the JSON-bridge between Python and Astro with native Astro Content Collections if i18n + type generation becomes painful.
- **Analytics.** Out of scope by parent spec, but Plausible / GoatCounter would be a small drop-in if ever wanted.

## 10. Open decisions deferred to implementation

- **Exact `SITE_DOMAIN` string** — final pick during implementation.
- **Satori font** — IBM Plex Sans (to match the site) preferred; fall back to Inter if Plex packaging is painful.
- **Tooltip styling fine-tune** — small dark pill vs. light card; pick during impl based on which reads better on the actual charts.
- **`og:type` for the homepage** — `profile` vs. `website`. `profile` is more specific. Decision at impl time after checking crawler behavior.
- **`<link rel="canonical">` trailing slash** — must match Astro's `trailingSlash: "always"` output. Implementation verifies on built HTML.
- **Whether to keep the github.io URL as a redirect or hard-cut to custom domain.** Recommend keeping as fallback (GitHub Pages handles both routes automatically), updating only the README + JSON-LD `Person.url` to the new canonical.
